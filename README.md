# Shop Admin

Админ-панель интернет-магазина: обзор показателей, товары, заказы, клиенты и настройки.

Стек: **Nuxt 4, Vue 3, TypeScript, Pinia, Vitest**. Работает как SPA и публикуется на GitHub Pages.

## Статус

Готово:

- макет с боковым меню и шапкой, адаптивный — на телефоне меню выезжает по кнопке;
- страницы «Обзор», «Товары», «Заказы», «Клиенты», «Настройки»;
- светлая и тёмная тема (или как в системе), выбор запоминается;
- типы данных магазина, функции форматирования цен и дат с тестами;
- **товары**: демо-каталог из 46 позиций в хранилище Pinia, таблица с сортировкой по любому столбцу, поиском по названию и артикулу, фильтрами по категории и статусу, постраничным выводом; подсветка товаров, которые закончились или заканчиваются;
- **форма товара**: добавление, редактирование и удаление с подтверждением; проверка полей (обязательные поля, формат и уникальность артикула, целая цена, нельзя выставить в продажу товар без остатка); ошибки показываются после ухода с поля, фокус переходит к первому полю с ошибкой;
- **заказы**: 90 демо-заказов за последние 60 дней, вкладки по статусам со счётчиками, поиск по номеру и клиенту, постраничный вывод; карточка заказа с составом, итогом, клиентом и историей статусов; смена статуса только по разрешённым шагам (новый → оплачен → отправлен → доставлен, отменить можно до отправки) с подтверждением отмены;
- **обзор**: выручка, число заказов, средний чек и покупатели за 30 дней со сравнением с предыдущими 30 днями; график выручки по дням на SVG с подсказкой при наведении; последние заказы, товары, которые заканчиваются, и лидеры продаж;
- **клиенты**: список с поиском по имени, email, телефону и городу, сортировкой по сумме покупок, числу заказов, дате последнего заказа и имени; профиль клиента с контактами, суммой покупок, средним чеком и всеми заказами; из заказа можно перейти к клиенту;
- **роли**: администратор и менеджер, переключаются в шапке (демо-вход без пароля). Менеджер добавляет и редактирует товары и меняет статус заказов, но не может удалять товары, отменять заказы и заходить в настройки — лишние кнопки и пункты меню скрыты, а прямой переход по адресу перехватывает middleware;
- **настройки**: название магазина (показывается в меню), описание ролей, сброс демо-данных с подтверждением;
- каталог и заказы сохраняются в localStorage и переживает перезагрузку; кнопка «вернуть демо-данные» восстанавливает исходный каталог;
- фильтры, сортировка и номер страницы хранятся в адресной строке — ссылкой на отфильтрованный список можно поделиться, кнопка «назад» работает;
- проверка тестов и типов и публикация через GitHub Actions.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # режим разработки
```

| Команда | Что делает |
|---|---|
| `npm test` | тесты (Vitest) |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run generate` | сборка статического сайта в `.output/public` |

## Структура

```
app/
  app.vue              корневой компонент
  layouts/default.vue  общий макет: меню, шапка, содержимое
  pages/               страницы — маршруты создаются по именам файлов
  components/          AppSidebar, AppHeader, PageHeader, StatusBadge, DataPagination,
                       ProductForm, ConfirmDialog, AppToasts, OrderStatusBadge, RevenueChart, KpiCard
  middleware/          permissions.global.ts — проверка прав перед переходом на страницу
  composables/         useTheme, useToast
  utils/validation.ts  проверка формы товара
  stores/              хранилища Pinia: products, orders, session (роль и название магазина)
  data/                генераторы демо-данных: товары, клиенты, заказы
  utils/orders.ts      статусы и разрешённые переходы, фильтры, сумма заказа
  utils/analytics.ts   выручка по дням, показатели за период, лидеры продаж
  utils/customers.ts   статистика клиентов, поиск и сортировка
  utils/permissions.ts роли и права: can(role, action)
  utils/table.ts       поиск, фильтры, сортировка, страницы
  utils/format.ts      цены, даты, склонение слов
  types/               типы: товар, заказ, клиент
  assets/css/main.css  цвета и общие стили
tests/                 тесты
```

## Как устроено

- Маршруты строятся автоматически из папки `app/pages`, компоненты и функции из `components`, `composables` и `utils` Nuxt подключает сам — без ручных импортов.
- Таблица товаров собирается цепочкой computed: фильтр → сортировка → страница. Каждое звено пересчитывается только когда меняются его входные данные. Сами операции — чистые функции в `utils/table.ts`, они покрыты тестами отдельно от Vue.
- Состояние таблицы живёт в `route.query`, а не в локальных переменных: адрес — единственный источник правды.
- Демо-данные генерируются детерминированно (псевдослучайные числа с фиксированным зерном), поэтому каталог одинаковый при каждой загрузке и в тестах.
- Проверка формы — чистая функция `validateProduct()`: на вход черновик и текущий каталог, на выход объект ошибок по полям. Форма только решает, когда их показывать. Одна функция работает и для создания, и для редактирования (свой артикул не считается дублем).
- Переходы статусов заказа описаны таблицей `TRANSITIONS`: интерфейс показывает только разрешённые действия, а `withStatus()` дополнительно проверяет переход и бросает ошибку, если он запрещён. Каждая смена записывается в историю заказа.
- В позиции заказа название и цена копируются в момент покупки, поэтому изменение товара в каталоге не меняет старые заказы.
- График выручки — свой компонент на SVG без библиотек: `viewBox` задаёт внутренние координаты, ширина подстраивается под контейнер, максимум оси округляется до «красивого» числа. Отменённые заказы в выручку не входят.
- Права описаны в одном месте — таблица `RULES` в `utils/permissions.ts`: у администратора все действия, у менеджера — список разрешённых. Компоненты спрашивают `session.can('orders.cancel')` и не знают, у какой роли что есть. Страница объявляет нужное право через `definePageMeta({ permission: 'settings.view' })`, а глобальный middleware проверяет его перед каждым переходом. Если роль сменили, находясь на закрытой странице, — переводит на обзор. В настоящем проекте роль приходила бы с сервера, и сервер проверял бы права ещё раз: скрытая кнопка — это удобство, а не защита.
- Статистика клиентов считается за один проход по заказам (`Map` по id клиента), а не отдельным перебором для каждого клиента.
- Окно подтверждения сделано на встроенном `<dialog>`: браузер сам удерживает фокус внутри и закрывает окно по Esc.
- Тема хранится в атрибуте `data-theme` у `<html>`; все цвета заданы CSS-переменными, тёмная тема переопределяет только их.
- `ssr: false`: админ-панели не нужна индексация поисковиками, поэтому она собирается как SPA и лежит на статическом хостинге.

## Публикация

Workflow `.github/workflows/deploy.yml` при пуше в `main` запускает тесты и проверку типов, собирает сайт и публикует его на GitHub Pages. В настройках репозитория нужно один раз выбрать Settings → Pages → Source: «GitHub Actions».
